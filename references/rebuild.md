# API重建与验收

## 实现

按当前presentations skill选择API、生成库、字体与渲染器。常规制作不要求启动桌面软件，可用Office/WPS自动化时如实记录用途和版本。新建从空白页开始，续做按workflow.md确定复用范围。

按edit-plan.json逐对象实现。文字匹配字体风格、字号、粗细、重点色、行距、对齐和换行；表格匹配列宽、行高、底板、边框和标签；流程匹配模块比例、图标语义、颜色与层级。公共函数须接受本页样式参数，库内组件只有匹配或充分调整后才可使用。素材融合与对象复杂度按lightweight.md处理。

选定设计是还原目标，不以通用标题加正文、统一色块、普通图标或删减内容替代原来的构图、纹理、笔触和装饰。完整含字设计图不能整页铺底，也不能把带字区域叠透明文本框冒充原生编辑层。

遇到接口缺失或效果不符，定位建模、参数、字体、图层或导出问题；查Microsoft/WPS及所用API/库的官方资料，核对版本并实际测试。记录页码、对象、问题、官方链接、尝试、结果和残余差异。已按方案采用独立图片的装饰不属于原生实现失败。

保存代码或操作记录，以及计划对象与导出对象的对应关系。先完成复杂代表页的字体、路径、渐变、分组和裁切验证，再推广到全套。

## 检查与修复

1. 基本检查：文件可读、页数、内容覆盖、资源关系、对象类型、边界、溢出及素材完整性。导出或校验失败时停止依赖步骤，不把旧候选文件当作本次结果继续交付。
2. 编辑检查：按editability.md在副本实测声明能力，交付文件不保存测试修改。
3. 性能检查：按lightweight.md记录对象复杂度和实际可测表现。
4. 视觉检查：渲染全部实际候选PPTX页，逐页逐对象对照设计。先查总体布局比例，再查字体、颜色、换行、图形、渐变、圆角、阴影、笔触和装饰。代码预览与原设计图不能冒充交付渲染。

具体差异修实现，困难先官方查证；修改后重新导出受影响页。visual-review.json记录候选文件版本、工具版本、页码、对象差异、修复和状态，检查证据必须来自最终交付版本。以这些证据验收，不使用相似度阈值、百分比或笼统的自评。

## 交付

默认交付PPTX，不默认导出PDF。说明实际生成和渲染工具、原生可编辑范围及独立图片范围。结构、视觉和编辑检查分别陈述，未实测的应用兼容性或性能如实标明。

未达标对象继续修复。官方查证和合理实测后仍受素材、字体、接口或格式限制，可交付当前结果，但逐项说明页码、对象、目标、当前差异、官方链接、实测及使用影响，标记部分完成。检查受阻标为未验证，不能宣称完整还原，也不无限重试同一失败方法。

查询或收录组件时可使用scripts中的PowerPoint辅助脚本；其依赖和参数见libraries.md，常规API制作不以这些脚本为前提。
